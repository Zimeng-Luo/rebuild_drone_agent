## 三、与传统流程的基线复现

报告表 3、图 7、图 8 与 PPT 第 15、16 页的 COLMAP 数据由下列两条脚本在同一批 81 帧上真实跑出，未引用任何外部二手数字。

```bash
cd /home/zimeng/rebuild_drone_agent
PY=/home/zimeng/miniconda3/envs/rebuild_drone_agent/bin/python

# 1. 从 aligned.npz 还原主样例的那 81 帧，导出为 jpg
$PY scripts/baseline_extract_frames.py \
    --video data/example/主楼02.MP4 \
    --npz data/result/workbench/<job_id>/<task_id>/aligned.npz \
    --out data/result/baseline_colmap/images --extract-fps 3.0

# 2. 稀疏重建并四阶段计时，结果写 baseline_summary.json
$PY scripts/baseline_colmap.py \
    --images data/result/baseline_colmap/images \
    --work data/result/baseline_colmap/run --overlap 10

# 3. 生成耗时与密度对比图、点云双栏对比图
$PY scripts/fig_compare_pointcloud.py
```

实测结果（`baseline_summary.json`）：81 张输入、注册 79 张、50 920 点、平均轨迹长度 6.15、平均重投影误差 0.76 px、总耗时 1595.72 秒（特征提取 746.34、顺序匹配 61.24、增量重建 788.12）、ply 0.76 MB。

复现时请注意三点：`pycolmap` 的 wheel 不带 CUDA，因此只做稀疏 SfM，不做 PatchMatch 稠密化；`--overlap` 与 `max_image_size` 会显著影响注册数与耗时，报告里的数字对应 `overlap=10`、`max_image_size=3200`；日志里 `sift.cc` 与 `feature_extraction.cc` 会刷屏，看进度请 grep `num_reg_frames`。

## 六、复现口径

1. 点云坐标是模型推断的相对值，未接入外部控制点时不含绝对尺度。
2. 序列长度的实测范围是 2 分钟量级（81 帧、5 分块）；更长的序列会切更多块，显存不随之增长。
3. 回环搭配 IRLS 全局优化，本样例 3 对候选全部被接受，优化器是否生效可在 `alignment_evidence.json` 中查证。
4. `aligned.glb` 承载的是带颜色的点云，用于浏览器内快速查看与交互。
5. 性能数字来自单卡单任务实测，设备为 RTX 4090，显存 24 GB。
